Develop

The theme has no compile step: PHP templates and plain CSS ship as they are. npm exists only to vendor Bootstrap, build the distributable zip and run the checks.

Install for development

Clone the repository into wp-content/themes/ (or symlink the wpwisebones/ folder there), and put wisebones-shortcodes/ in wp-content/plugins/.

git clone https://github.com/ibuilder/WPWiseBones.git
cd wpwisebones/wpwisebones
npm install          # bootstrap 5.3.3, bootstrap-icons 1.11.3, archiver

Prerequisites: Node.js 18+ with npm 9+, PHP 7.4+ for the syntax checks and test runner, and WP-CLI if you want to regenerate the translation template.

npm scripts

Run these from inside wpwisebones/.

CommandWhat it does
npm run syncRe-copies Bootstrap and Bootstrap Icons from node_modules/ into assets/vendor/
npm run potRegenerates languages/wpwisebones.pot with WP-CLI
npm run zipBuilds wpwisebones.zip, honouring .distignore
npm run preflightProduction-readiness check — must report zero errors before a release
npm testRuns the integration tests against a real WordPress install
npm run pot shells out to a Windows WP-CLI path (C:\Server\wp-cli.phar). On macOS or Linux, run wp i18n make-pot . languages/wpwisebones.pot --domain=wpwisebones directly instead.

Tests

tests/run.php is a dependency-free integration runner — no PHPUnit, no Composer. It borrows a real WordPress install, loads the theme against it, and puts the active-theme option back when it is done. Point it at an install with an environment variable if it can't find one:

WPWISEBONES_TEST_WP=/path/to/wordpress php tests/run.php

The current suite covers asset enqueueing and the dashboard widget.

The preflight check

scripts/preflight.js is the gate before packaging. It verifies, among other things:

  • Required files exist, and style.css carries every required header
  • The text domain matches the folder name, and every __() call uses it
  • Every PHP file has an ABSPATH guard and every function uses the theme prefix
  • screenshot.png, license.txt and the vendored Bootstrap files are present
  • theme.json parses, the SEO and WooCommerce includes are in place, and the dashboard widget registers
  • The .pot file exists and carries a realistic number of strings

Release checklist

Bump the version in all four places, or the preflight and WordPress disagree about which version is installed:

  • wpwisebones/style.css → Version:
  • wpwisebones/functions.php → define( 'WPWISEBONES_VERSION', … )
  • wpwisebones/package.json → "version"
  • wpwisebones/readme.txt → Stable tag: plus a changelog entry
cd wpwisebones
npm run preflight    # must pass with 0 errors
npm run zip          # writes ../wpwisebones.zip

WordPress.org compliance

The theme is written to the Theme Review Guidelines, and the plugin to the Plugin Directory guidelines. The rules that shape the code most:

  • No plugin territory in the theme. Shortcodes live in the companion plugin, which is why wisebones-shortcodes exists at all.
  • No remote assets. Bootstrap and its icons are vendored into assets/vendor/ and served locally.
  • Everything escaped and sanitised. Every Customizer setting has a sanitize_callback; output goes through esc_html(), esc_attr(), esc_url() or wp_kses_post().
  • Correct prefixes. wpwisebones_ in the theme, wpbs_ in the plugin, for every function, class and global.
  • Text domain equals folder slug, with a committed .pot.

How this site and its screenshots are built

Every screenshot here is produced from the project's own code — no mock-ups. tools/docs-screenshots/ holds a small WordPress API stub that is enough to execute the themes' templates and the plugin's shortcode callbacks outside WordPress, render them to static HTML with the real stylesheets, and photograph the result with headless Chromium.

FileRole
wp-stub.phpMinimal WordPress API — escaping, i18n, hooks, the shortcode parser, the loop, template loading
sample-data.phpPlaceholder images and sample posts shared by the renderers
render.phpEntry point: renders the theme front pages and the shortcode demos
render-theme.phpBoots one theme (parent or child) and renders its front page
render-shortcodes.phpRuns all 17 shortcodes and writes the demo page plus a JSON manifest
capture.mjsPlaywright: screenshots each page and each shortcode element
build-shortcodes-page.phpRegenerates the marked-up block in docs/shortcodes.html from the manifest
set-image-dims.phpStamps each screenshot's real dimensions onto its <img>, so the lazy-loaded images reserve their space and anchor links land accurately
 
# from the repository root
php tools/docs-screenshots/render.php build
node tools/docs-screenshots/capture.mjs build docs/assets/img
php tools/docs-screenshots/build-shortcodes-page.php build docs
php tools/docs-screenshots/set-image-dims.php docs

The capture step needs Playwright's chromium package; set CHROMIUM_PATH if your browser lives somewhere other than Playwright's own download directory. Because the attribute tables are read out of shortcode_atts() at build time, they cannot drift from the plugin source.

The stub is a documentation tool only. It is not loaded by WordPress and is excluded from the distributable zips.
